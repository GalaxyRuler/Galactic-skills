# Distinctive Design Gates

## Overview

The user consistently rejects generic, AI-default design: template card grids, stock gradient heroes, interchangeable SaaS aesthetics. Run these deny-gates before presenting any design. A design that fails a gate is not shown — iterate first. This is a standing rule.

## When to use

Use this when:
- Presenting any web/UI design, mockup, landing page, or redesign.
- Iterating after a design rejection.
- Reviewing design work another agent produced before it reaches the user.

## Deny-gates (all must pass before presenting)

1. Not generic
- Would this design be recognizable among ten AI-generated sites for the same brief? If it could be anyone's site, it fails.
- Default-stack tells (uniform card grids, gradient hero + three feature columns, stock icon rows, purple-on-dark SaaS defaults) fail unless deliberately subverted.

2. Meaningfully different from rejected iterations
- Each new iteration must change layout structure AND type system AND visual concept relative to rejected ones. A recolor or reskin of a rejected skeleton fails.
- Keep a written list (in the session or a scratch file) of rejected directions and what was rejected about each; check new work against it before presenting.

3. Full pages, not fragments
- Present complete rendered pages, top to bottom. Cropped sections and isolated components hide the overall impression the user judges by.

4. Identity preserved
- The user's stated identity, content requirements, and multi-facet positioning must survive the redesign. A beautiful page that erases required content fails.

5. Grounded direction
- Anchor each direction in distinctive real-world references (found via online search when needed), not in the model's default aesthetic.

## Workflow

1. Before designing, restate the identity/content constraints and the list of previously rejected directions.
2. Choose a distinctive concept and reference points; note what makes it non-generic.
3. Build the full page(s).
4. Run the five gates. Fail → iterate before showing anything.
5. Present with a one-line statement of the concept and how it differs from the last iteration.

## Verification checklist

- All five gates checked explicitly before presenting.
- Full-page render(s) included.
- Difference from prior rejected iterations is structural, not cosmetic.
- Required content and identity elements all present.

## Common failure modes

- Presenting the default component-library aesthetic and calling it a design.
- Recoloring a rejected layout and presenting it as a new direction.
- Showing hero-section crops instead of the full page.
- Dropping the user's required content to make the layout cleaner.
- Iterating inside one visual concept when the concept itself was rejected.
