# Back-end Testing Playbook (portable)

> Stack-agnostic methodology. Pair runner: `SKILL.md` (same folder). Fill the **Project appendix** per repo.

**Question:** is the service correct, contract-stable, data-sound, secure, resilient under failure, and fast enough — provably, on every change?

**Strategy framing:** shift-left (test from the dev phase, not pre-release), risk-based (effort on critical journeys + high-blast-radius code), **Testing-Trophy** shape: static base → thin unit (pure logic) → **integration as the widest layer** (real deps via [Testcontainers](https://testcontainers.com/)) → thin E2E cap. Most bugs live at the boundaries between services, not inside units. ([Testing Trophy](https://kentcdodds.com/blog/the-testing-trophy-and-testing-classifications), [harness load 2026](https://www.harness.io/blog/load-testing-an-essential-guide-for-2026))

---

## Phases (gate each before the next)

### 0 — Scope & map
Enumerate endpoints (from the OpenAPI/GraphQL spec + route files), the data model (ORM/schema), external deps (DB, cache, queues, third-party APIs, jobs), and the **invariants** that must never break. Note the **SLOs** and the **critical journeys** (login, checkout, the money path). Output: endpoint × method × auth-context list + dependency map.

### 1 — Static base
Type-check / lint. Treat the **schema (zod / OpenAPI / JSON-Schema / protobuf) as the contract source of truth** — it validates inputs at the edge and defines response shape. ([Zuplo](https://zuplo.com/learning-center/how-api-schema-validation-boosts-effective-contract-testing))

### 2 — Unit (pure logic)
Pure functions in isolation: business math, normalization, validators, scoring. Where a known-correct reference exists, assert against a **golden master held independently of the code under test** (a fixture generated by the same engine can't catch that engine's bugs).

### 3 — Integration (the widest layer)
Spin **real** dependencies (DB, cache, queue) with Testcontainers / compose. Boot the app and exercise routes via an in-process injector (no network flake). Per endpoint: happy path, validation failures (bad/missing/oversized), not-found, **auth/permission boundary**. Assert DB side-effects, migration correctness, deterministic seeds, cache hit/miss + fallback.

### 4 — Contract
- Validate **both request and response** against the schema for every endpoint a client consumes — test **every status code** the spec declares; negative test per field. A response-shape change the client doesn't expect must fail CI.
- **Provider-side, spec-driven:** generate + run tests from the OpenAPI spec ([Schemathesis](https://schemathesis.readthedocs.io/) / Dredd) to catch spec↔impl drift.
- **Consumer-driven (microservices):** [Pact](https://docs.pact.io/) — the consumer's test generates a contract the provider verifies, so neither breaks the other.
- Detect **breaking changes** vs the committed contract (removed field, narrowed type, changed code). Run on every PR that touches API code. ([totalshiftleft](https://totalshiftleft.ai/blog/what-is-api-contract-testing))

### 5 — Data & invariants
Golden-master parity for critical computations; deterministic IDs; data-freshness / drift; correctness of ETL/sync jobs (idempotency, partial-failure isolation, staleness); **migration safety** (additive, reversible, no data loss).

### 6 — Resilience & chaos
Force each dependency to fail — DB/cache/queue/third-party **down, slow, or returning garbage** — and assert graceful degradation (serve last-good / documented fallback), consistent error shape, sane timeouts, retry/backoff, no unhandled rejection, and rate-limit under burst. Mature form = **chaos engineering**: hypothesis-first, tied to SLIs/SLOs, safety-constrained, repeatable in CI; combine **Load + Chaos** (inject latency / kill a pod under traffic) to test resilience under stress + failure together. ([AWS Well-Architected REL12-BP04](https://docs.aws.amazon.com/wellarchitected/latest/reliability-pillar/rel_testing_resiliency_failure_injection_resiliency.html), [netalith chaos](https://netalith.com/blogs/quality-assurance/chaos-engineering-resilience-testing-2026))

### 7 — Security — OWASP API Security Top 10 (2023)
Walk the list against documented endpoints, across roles/tenants ([OWASP API 2023](https://owasp.org/API-Security/editions/2023/en/0x11-t10/)):
- **API1 BOLA** (#1, ≈40% of API attacks): **two-account test** — account A must not read/modify B's objects by changing an ID. Server-side ownership check on **every** object **every** request; never trust user-supplied IDs for authz. (Most scanners test only one session — BOLA needs two.) ([practical-devsecops](https://www.practical-devsecops.com/owasp-api-security-top-10/), [Salt](https://salt.security/blog/owasp-api-security-top-10-explained))
- **API3 BOPLA / API5 BFLA:** property- and function-level authz.
- **Injection:** parameterized queries (ORM) + schema validation block SQL/NoSQL/command injection; fuzz inputs.
- **API7 SSRF:** any endpoint/job fetching a **user-influenced URL** validates scheme + host allow-list before fetching.
- **API4 resource consumption:** pagination caps, body-size limits, rate limiting (and `trustProxy` so limits key on the real client IP behind a proxy).
- **API8 misconfiguration:** security headers, scoped CORS, secrets never in responses/logs, errors don't leak stack/internal detail.
- **API10 unsafe consumption:** validate/sanitize upstream data before persistence (incl. PII redaction).
- **DAST** mapped to the Top 10 in CI ([OWASP ZAP](https://www.zaproxy.org/) — passive always-safe; active = real attack, non-prod only; seed it with the OpenAPI spec).

### 8 — Performance & SLOs
Define SLOs (p95/p99 latency, error rate) from Phase 0 and encode them as **test thresholds** ([k6](https://k6.io/) / Gatling / JMeter / Locust). Shape: ramp-up → steady → ramp-down on the critical journeys; watch cache effectiveness + connection pools under load. Shift-left: run a smoke load on every PR, full load before release.

### 9 — Report
Findings table (Conventions). Map security findings to their **OWASP API ID**; state performance vs the **SLO**; call out contract diffs explicitly. Lead with security S0/S1 + any broken invariant.

## Conventions (shared)
**Severity:** S0 blocker · S1 critical · S2 major · S3 minor · S4 polish.
**Finding schema:** `ID · Severity · Endpoint/Area · Evidence · Rule (OWASP ID / SLO / invariant) · Recommendation`.
**Safety:** run only against **local/test** instances; active DAST + load tests are attacks — never point them at production. Use a test env + deterministic seed.
**Anti-degraded-pass:** a phase that can't run (no containers, no spec, no load tool) = **NOT VERIFIED** in the report + a one-line setup note — never silently "pass."
**Report path:** `docs/testing/reports/<YYYY-MM-DD>-backend.md` if that dir exists, else `./backend-test-report-<YYYY-MM-DD>.md`.
